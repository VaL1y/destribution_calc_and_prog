# Чем отличаются repmgr, Patroni и координаторы

Это инструменты разных уровней.

## repmgr/repmgrd

- специализирован только на PostgreSQL;
- использует PostgreSQL streaming replication;
- хранит метаданные кластера в PostgreSQL;
- не требует отдельного DCS;
- проще для первого стенда;
- слабее защищает от неоднозначного сетевого разделения без witness/fencing.

## Patroni

- специализирован на управлении PostgreSQL;
- следит за процессом, выполняет promotion, rewind/reinitialize и switchover;
- сам не является consensus-хранилищем;
- использует внешний DCS для leader lock и общей конфигурации.

То есть Patroni автоматизирует PostgreSQL, а etcd/Consul/ZooKeeper сообщают ему,
какой узел имеет исключительное право быть лидером.

## etcd

- распределённое key-value хранилище;
- consensus: Raft;
- сильная сторона: lease, watch и атомарные операции над небольшим состоянием;
- часто используется Kubernetes и Patroni;
- обычно самый прямой DCS для нового Patroni-кластера.

## Consul

- также использует Raft для серверного consensus;
- кроме key-value даёт service discovery, DNS и health checks;
- полезен, если эти функции уже нужны всей инфраструктуре;
- для одного PostgreSQL-кластера возможностей больше, чем требуется.

## ZooKeeper

- зрелый координатор с иерархическими znode и watch;
- использует протокол ZAB, а не Raft;
- работает на JVM;
- распространён в экосистемах, где уже есть Kafka/Hadoop-совместимые системы;
- с нуля для одного PostgreSQL обычно тяжелее по эксплуатации, чем etcd.

## Встроенный Raft Patroni

Patroni умеет использовать Python-реализацию Raft без отдельного etcd. Однако
этот backend помечен разработчиками Patroni как deprecated. Для учебного опыта
он уменьшил бы число контейнеров, но учил бы строить новую систему на механизме,
от которого проект планирует отказаться. Поэтому его здесь не используем.

## Практический выбор

```text
Сейчас:         PostgreSQL + repmgrd
Позже, если нужен строгий consensus:
                PostgreSQL + Patroni + etcd
Если Consul уже обслуживает всю инфраструктуру:
                PostgreSQL + Patroni + Consul
Если ZooKeeper уже является стандартом организации:
                PostgreSQL + Patroni + ZooKeeper
```

etcd не является обязательной частью PostgreSQL. Она становится обоснованной,
когда мы требуем автоматический failover и одновременно хотим безопасно решать
сетевые разделения через leader lock и большинство независимых голосов.
