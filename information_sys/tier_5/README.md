# Tier 5 — PostgreSQL + Patroni + ZooKeeper

Тот же складской HA-стенд и то же размещение, что в `tier_4`, но распределённое
решение хранится в ZooKeeper, а не в etcd.

```text
Удалённый сервер                         Локальный сервер
┌──────────────────────────────┐         ┌────────────────────┐
│ FastAPI                      │         │ pg-3 + Patroni     │
│ pg-1 + Patroni               │◄───────►│ ZooKeeper-3        │
│ pg-2 + Patroni               │  VPN/LAN│ (голос 3)         │
│ ZooKeeper-1, ZooKeeper-2     │         └────────────────────┘
│ (голоса 1 и 2)               │
└──────────────────────────────┘

Обычная рабочая машина: ничего не запущено.
```

Patroni использует ZooKeeper как DCS: там лежат лидерский lock, конфигурация и
состояние участников, но не таблицы склада. Кворум равен 2 из 3. Репликация самих
данных по-прежнему выполняется PostgreSQL через WAL.

Гарантии и ограничения совпадают с `tier_4`: отказ одной ноды переживается,
удалённая сторона сохраняет кворум при разрыве связи, локальная сторона одна не
повышается. Полная потеря удалённого сервера не переживается автоматически и
также убирает единственный FastAPI.

Не запускайте `tier_4` и `tier_5` одновременно на тех же адресах: их стандартные
порты PostgreSQL, Patroni и API совпадают.

Далее: [пошаговый запуск](docs/01-start.md) и [сценарии отказов](docs/02-failures.md).
